# Shared SDK catalogs

`dslvm::Registry` installs the complete standard library (`string`, `math`, `collections`, and `file`) by default from the pinned `lmcode-cpp` bundle (`ee1f084927668260507af277cbb1e7c2accd74e1`). `Message.header_names` returns an independent SDK `StrList` snapshot allocated through `reg.std_collections()`. Its mutable superset edits only that returned collection, never message headers; native `Message` and `Url` storage remain separate. Collection handles live for a chunk run, and `Program::run` resets the standard collection arena on entry and exit. SDK bounds errors and byte semantics apply unchanged.

`scripts/sync-sdk.sh` vendors `cpp/dslvm.hpp`, all six `cpp/stdlib/*.hpp` headers (including `cpp/stdlib/file.hpp` for `file_read`, `file_write`, `file_append`, `file_exists`, and `file_lines`), `cpp/std/lmcode-std.schema.json`, and `scripts/merge-std.py` from one pinned commit. `sdk.lock` stores `commit=` and all nine per-file SHA-256 entries; `scripts/sync-sdk.sh --verify` checks every vendored file. `schema/lmproxy.host.json` is the checked-in host-only declaration source; CMake copies its exact bytes to git-ignored `schema/lmproxy.dsl.json` for embedding, while `lmscript >= 0.2.420` supplies the 72 built-in standard declarations implicitly.

The full Squid engine is built statically from `third_party/squid` using `scripts/build-squid.sh`, embedding client/server connection handling, forwarding, memory caching, and SSL-bump TLS interception, linking OpenSSL statically and glibc dynamically on Linux.
